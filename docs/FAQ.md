# FAQ：IP、许可证、私有 API、系统版本与分发

> 这不是法律意见。公开或商业发布前，请让律师确认。

## 1. 不开源、不盈利，可以用 Chiikawa 角色吗？

**不可以默认认为可以。** 不盈利不等于获得授权：

- 角色形象受版权保护，公开仓库和 Release 属于公开分发。
- 角色名/标识可能涉及商标；把它用作产品主题名，可能让人误以为官方联名。
- 权利人通常对个人 fan art 较宽容，但宽容不是许可，也不能保证不会被下架。
- 开源后别人可以再分发，风险会被放大。

更稳妥的做法：

- 公开版换成原创吉祥物（保留蓝/粉/黄配色即可）。
- 或者只在本地个人使用，不公开带这些素材的构建。
- 如果确实想用，先取得权利人书面许可。

## 2. 可以把 GPLv3 改成 MIT 吗？

不能直接改。许可证取决于代码版权：

- `Vendor/PelmetCore`、`Vendor/PelmetEngine` 来自 Dimble，是 **GPLv3**。
- 把它们链接进同一个 app 并分发时，整个组合作品要按 GPLv3 提供源码。
- 你自己的原创代码可以单独 MIT，但只要最终二进制包含 GPLv3 代码，就不能把整个项目改成 MIT。
- 想 MIT，只有两条路：移除/重写所有 GPLv3 代码，或把 GPL 部分拆成独立进程并让律师确认边界。

GPLv3 与是否盈利无关：它允许收费，但要求源码、许可证和修改说明。角色 IP 是另一套权利，和代码许可证无关。

## 3. 私有 API 是什么？还需要做接口吗？

不是网络接口。`MenuBarClientCore` 是 macOS 未公开的系统框架接口，Dimble/Pelmet 用它创建“评估模式”断言来隐藏菜单栏项目。

- 没有公开 API 可以隐藏第三方菜单栏项；这是目前能稳定做到的方式。
- 它没有兼容性承诺，macOS 更新可能失效；App Store 不接受。
- 打包成 .app 不会消除这个依赖，只是把风险藏进 app 里。
- 工程上应做能力探测、失败降级和兼容性测试，而不是再写一套“接口”。

## 4. 怎么让别人一键用上？

推荐顺序：

1. **GitHub Release + 签名/公证的 .app**：用户下载 DMG/zip，拖进 Applications。
2. **Homebrew Cask**：`brew install --cask youngbar`，升级也走 brew。
3. **安装脚本**：`curl -fsSL .../install.sh | sh`，下载最新 Release、移动到 /Applications；适合其他 Agent，但要说明 Gatekeeper 与权限。
4. **源码构建**：`git clone && sh Scripts/build.sh && open build/YoungBar.app`，适合开发者和 Agent。

辅助功能必须由用户在系统设置里手动授权，任何安装方式都不能完全自动化。没有 Developer ID 时只能 ad-hoc 签名，权限可能因重建而重置。

## 5. 还缓存菜单栏截图吗？

不缓存。5.5 起删除了 `StatusPictures` 和菜单栏像素缓存：收纳条显示应用图标（系统项用 SF Symbol），不抓取、不保存菜单栏内容，也不需要屏幕录制。`~/Library/Application Support/YoungBar/` 现在只保留设置诊断、测试 JSON 和事件记录 `events.log`（••• 的位置变化、屏幕和桌面变化、图标名称，不含窗口内容；复制诊断信息时会带上最近的部分）。

## 6. 支持 macOS 12 / 13 / 14 / 15 / 26 吗？

不支持。YoungBar **只支持 macOS 27 及以上**；macOS 27 只能装在 Apple 芯片的 Mac 上，所以 Intel Mac 也用不了。

- 从 0.1.0 起，每个版本的 `Info.plist` 都写着最低 macOS 27.0（`LSMinimumSystemVersion`），更早的系统会直接拒绝打开。安装命令会先检查系统版本，低于 27 就提示并退出，不下载、不改动任何东西。
- 原因不在版本号：隐藏用的是 macOS 27 的 `MenuBarClientCore` 评估模式（见第 3 条），排序靠改写 macOS 27 菜单栏（`MenuBarAgent`）记录的图标位置。引擎只为 macOS 27 写过、也只在 27 上验证过；要支持更早的系统，得另写一套隐藏和排序的办法，界面里用到的较新的系统接口（例如设置窗口的玻璃效果）也要给旧系统另做一份。

## 7. 为什么有的应用设成「显示」，菜单栏上还是没有？

多半是因为这个应用**没有 Apple 签发的签名**：自己编译的应用，或从 GitHub 等地方下载、没做开发者签名的应用。

- YoungBar 隐藏图标用的是 macOS 27 自带的机制：交给系统一份「允许留在菜单栏的应用」名单，名单外的都藏起来，由系统执行。
- 实测发现，系统只认有 Apple 签发签名（Developer ID、Apple 自带）的应用。没有的，就算在名单里，**只要有任何一个图标被隐藏**，它的图标也会被一起藏起来；一个都不隐藏时不受影响。Apple 没有文档说明这条规则，以上是 2026-11-10 在 macOS 27.0.1 上对比自签名应用和 Developer ID 应用得出的。
- 0.2.0 起，YoungBar 按签名认出这类应用：只要有别的图标被隐藏，它们就在收纳条里，从收纳条可以点开。设置的菜单栏页里它们单独一段「系统不显示：固定在收纳条里」，不能单独设成显示或隐藏，也不能拖：设成哪个，系统都不显示它。
- 想让它回到菜单栏：要么一个图标都不隐藏，要么给它换成 Apple 签发的证书（Developer ID 实测有效；免费 Apple ID 的 Apple Development 证书没试过）。
- 查一个应用的签名：`codesign -dv /Applications/某应用.app`，`Authority=` 里有 `Developer ID Application` 或 `Apple` 的就是有。
- YoungBar 自己也是自签名的，所以隐藏生效时它自己的占位项也不显示；••• 是浮在菜单栏上的，不受影响。
